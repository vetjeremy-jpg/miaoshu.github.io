# Moonlit Stories 第一批內容發布清單

> 依 Stable Maintenance 執行：先增加作品密度與讀者探索價值，不重新設計 production UI。

## 現況基線（2026-10-05）
- 小說書房：10 本皆已有首頁簡介與獨立閱讀入口。
- 《兩種天空》第一部：15 章、本部完結、閱讀時間、第一章入口已受 Reader Contract 保護。
- 札記：目前正式 journey dataset 只有 1 篇（2026-09-28 臺北大縱走第五段）。
- 攝影館：已有雪庭舞劍、林蔭午後、月映晚霞、台北夜色等系列與策展入口。
- 工程原則：沒有可重現 regression，不修改 Hero、首頁結構、CSS、PWA 或既有互動。

## Batch 1 — 先補內容密度
### P0｜札記
- [ ] 新增第 2 篇完整札記
- [ ] 新增第 3 篇完整札記
- [ ] 每篇具日期、標題、地區、摘要、正文、articleUrl
- [ ] 有可靠地理資料時才加入 location/座標；不猜測
- [ ] 時間軸依日期排序，地圖與文章入口一致
- [ ] 目標：先由 1 篇提升至 3 篇；後續累積到 5–8 篇

### P0｜小說內容 QA
- [ ] 不重寫目前已完整的 10 本首頁簡介
- [ ] 新增/修訂正文時逐章校對標題、順序、上一章/下一章
- [ ] 新作品發布前補齊作品狀態、閱讀時間與一句定位
- [ ] 《兩種天空》任何修訂不得破壞 15 章旗艦契約

### P1｜攝影策展
- [ ] 從既有系列選 1 組作為下一期主題作品集
- [ ] 保留 100–200 字策展文字
- [ ] 精選順序形成開場→發展→收尾
- [ ] 不為增加數量重複上圖
- [ ] 外部相簿/IG 失效時，站內作品仍可獨立成立

### P1｜作品關聯
- [ ] 為本期主推小說選 2 個真正相關的延伸作品
- [ ] 每個關聯寫清楚理由：主題／人物／地點／情緒／時代
- [ ] 關聯必須幫助「讀完 A → 想看 B」，不為星圖密度硬連

### P1｜月光來信
- [ ] 等 Batch 1 至少有一件真正的新內容再寄
- [ ] 1 段喵叔的話
- [ ] 1 件新作品
- [ ] 1 件值得回看的舊作品
- [ ] CTA 直接進作品
- [ ] 不為固定週期硬寄

## 本期策展更新條件
只有在新札記／新攝影作品集／小說實質更新至少一項完成後，才更新「本期選題／今夜三選」。不為了讓首頁看起來有變化而換文案。

## 每個內容 PR 的完成定義
1. 讀者價值可以一句話說清楚。
2. 首頁或分類頁有自然入口。
3. 作品本身完整，不依賴外部社群才能成立。
4. 讀完後至少有一個合理的下一步。
5. 適用 CI 全綠。
6. 發布後 320/375/390/430 與 iPhone PWA 無可重現 regression。
7. 沒有無關 UI/CSS 修改。

## 停止條件
當一個內容 PR 已符合以上七項，就停止「順手優化」。下一個投入應是下一件作品，而不是繼續調整同一頁。
