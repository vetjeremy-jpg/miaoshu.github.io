# Moonlit Stories｜讀者體驗量測契約 v1（設計稿）

> 狀態：Specification only。**不部署追蹤程式、不寫入 cookie、不發送事件、不收集讀者個資。**
> 本文件定義未來實作前的驗收準則；目前所有指標均為「尚無資料」，不得推估。

## 目標與分母

| 指標 | 事件與定義 | 分母 | 限制 |
| --- | --- | --- | --- |
| 閱讀開始率 | `reader_start`：讀者主動進入小說正文，且內容可見 | 作品入口有效到達次數 | 不等於獨立讀者 |
| 章節前進率 | `reader_next_chapter`：成功切換至下一章 | 已開始閱讀的工作階段 | 不以按鈕點擊代替成功切換 |
| 閱讀完成率 | `reader_complete`：抵達作品最後一章的明確結尾 | 已開始閱讀的工作階段 | 不推定讀者已完整讀完文字 |
| 探索到達率 | `explore_arrive`：從首頁作品入口抵達目標作品 | 作品入口啟動次數 | 不能跨裝置去重 |
| 訂閱成功率 | `subscribe_success`：訂閱服務確認成功 | `subscribe_submit` 次數 | 不以按鈕點擊當作成功 |

## 事件規格

- `reader_start`、`reader_next_chapter`、`reader_complete`：僅允許 `work_id`（預先核准的非個人作品代碼）、`chapter_index`（整數）、`event_version`。
- `explore_open`、`explore_arrive`：僅允許 `entry_id`（固定入口代碼）、`destination_id`（固定作品代碼）、`event_version`。
- `subscribe_submit`、`subscribe_success`、`subscribe_failure`：僅允許 `form_id`（固定代碼）、`event_version`；失敗原因不包含後端訊息或輸入內容。
- 不傳送姓名、Email、IP、使用者代理字串、完整 URL、查詢參數、閱讀內文、自由輸入欄位、持久識別碼、指紋或精確位置。
- 不將 `localStorage`、cookies 或裝置識別碼用於跨次／跨裝置追蹤；如未來採工作階段計數，必須另行定義邊界與隱私審查。
- 僅在使用者完成必要的隱私選擇且部署服務完成審查後，才能啟用任何實際資料傳送。

## 不可誤報的邊界

1. 沒有資料時顯示「尚未啟用量測」，不可顯示 0% 或假造樣本數。
2. 瀏覽器自動化測試只證明事件觸發條件正確，不代表真實讀者轉換率。
3. 訂閱成功只能由現有訂閱流程的明確成功回應確認；重複訂閱須依服務語意獨立標示。
4. 使用者拒絕非必要追蹤時，閱讀、導覽、訂閱、PWA 和朗讀功能必須維持正常。
5. 若未來部署，必須先審核資料處理者、保存期限、告知文字、同意／撤回機制、事件白名單與刪除策略。

- 在測試環境驗證同意前及拒絕後沒有分析請求，且沒有識別用儲存項目。
- 分別驗證小說兩本作品、首頁探索入口及 Newsletter 成功／失敗／重複訂閱情境。
- 先提供量測方案與隱私審查供核准，再以獨立 PR 實作；不得與版面或 PWA 改版混合。
